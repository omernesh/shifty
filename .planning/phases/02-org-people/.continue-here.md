## Unresolved Findings (the spike target)

Verbatim build error tail from hpg5 after the Confirm + If fixes:

### Finding 1: Page-level `auth: { roles: [...] }` is REJECTED by Lowdefy 5.3 (9 pages)

Pages using this pattern: manage_soldiers, soldier_detail, team_detail, roster_import, roster_import_result, manage_role_tags, my_profile, my_dashboard, manager_dashboard (Phase 1).

**Spike questions:**
1. Is `auth.pages.roles` at `lowdefy.yaml` top level (which Task 1 correctly populated) the canonical Layer-3 tenant-isolation gate?
2. If yes — confirm via a live cross-tenant probe (manager from tenant A POSTing to a tenant-B page route → expect 403/redirect).
3. If no — what IS the canonical 5.3 Layer-3 gate? Document it in `.claude/skills/lowdefy/reference/08-auth.md` BEFORE removing the page-level `auth:` blocks.

**PRD contract at risk:** PRD §8.3 says "every domain table has tenant_id; every query filters by session-derived tenant_id (never request input); four-layer defense (session → query filter → page auth → server-side request role check)". Missing the page-level gate IS a release blocker if Layer-3 is not enforced elsewhere.

### Finding 2: Action-level `if:` is REJECTED by Lowdefy 5.3 (3 confirmed, 11+ likely)

`.claude/skills/lowdefy/reference/07-events-and-actions.md:32` documents `if:` and `skip:` as valid optional action fields. Lowdefy 5.3.0 schema validator rejects both as additional properties. This is the W6 "Pattern A" column-dispatch foundation for `manage_org_units.yaml`'s tree-grid (the three-column action bar dispatches via `if: _event.column.field == 'col_X'` chained from `onCellClicked`).

**Spike questions:**
1. What IS the correct conditional-action pattern in Lowdefy 5.3?
   - Block-level `visible:` on the cellRenderer?
   - A switch action with `cases:`?
   - A custom plugin action that wraps the conditional?
   - Multiple action `Lists` per column (one trigger per column field)?
2. Pull from ctx7 `/websites/lowdefy` or the `lowdefy/lowdefy` GitHub source: `packages/engine` or wherever the action runtime lives.
3. Correct `.claude/skills/lowdefy/reference/07-events-and-actions.md` after the answer is known.

**UX contract at risk:** If `if:` is silently dropped at build time, every grid action fires for every column click — clicking "Add child" would also fire "Rename" and "Delete". Plan 03's W6 "Pattern A" implementation does NOT work without conditional dispatch.

### Finding 3: `TagSelector` block does not exist in Lowdefy 5.3 (2 pages)

`manage_soldiers.yaml:379` and `soldier_detail.yaml` (`soldier_form.role_tags`) both use `TagSelector`. The 5.3 validator's "Did you mean DateSelector?" is unhelpful.

**Spike questions:**
1. What canonical 5.3 block renders a chip-style multi-tag picker with autocomplete from an existing tenant tag list?
2. Candidate: `MultipleSelector` (Ant Design Select with `mode="tags"`). Verify field shape.
3. UI-SPEC §"Reusable components" expects chip-style — confirm the candidate block has chip rendering.

**UI contract at risk:** UI-SPEC commits to chip-style role tag input. Falling back to a plain comma-separated text input breaks the UX.
