## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → list_soldiers | Layer 1 (session-derived tenant_id) + Layer 2 (WHERE s.tenant_id = :tenant_id) + Layer 3 (auth.roles on page) + Layer 5 (RLS on soldier from 0009). |
| Browser → CreateSoldier plugin request | Plugin handler (plan 02 stub, plan 06 body) reads tenant_id from request.user.tenant_id — never from request.properties. Layer 4 defense. |
| `email` field | Server-side validation (`format: email` in CreateSoldier.schema from plan 02) + DB CITEXT collation on app_user.email (Phase 1 migration 0002). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing (tenant forgery) | list_soldiers, list_role_tags, list_leaf_teams, create_soldier_request | mitigate | All three KnexRaw blocks set `payload.tenant_id: { _user: tenant_id }`; CreateSoldier plugin request reads from `request.user.tenant_id`. Plan 10's tenant-isolation E2E forges a tenant-B id and confirms 0 rows / 403. |
| T-02-02 | Information Disclosure (cross-tenant leak via list query) | list_soldiers | mitigate | RLS on soldier from migration 0009 is the final layer. tests/e2e/cross-tenant-leak.spec.ts auto-discovers manage_soldiers and asserts no tenant-B id in response body. |
| T-02-05 | Tampering (XSS via display_name in AgGrid cell) | display_name cellRenderer | mitigate | Default AgGrid `field: display_name` uses text rendering (no innerHTML). The `_nunjucks` template for the role_tags valueFormatter and color cellRenderer is server-rendered by Lowdefy (no client `script` execution path). If the executor adds any html-rendering cellRenderer for display_name, it MUST escape — but the spec is text-only. Note: if a CSV-imported display_name contains literal `<script>`, plan 08's canonicalizeText does NOT strip HTML — that's a separate threat surface tracked in plan 08. |
