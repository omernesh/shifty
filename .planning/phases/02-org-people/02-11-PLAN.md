<objective>
Phase 02 was deployed but never runtime-verified. Live UAT (Plan 02-10 Task 4) surfaced that Lowdefy 5.3's plugin runtime does NOT register `requests`-only plugins — the three Phase-2 plugins (shifty-auth, shifty-roster, shifty-audit-writer) all declared `requests: [...]` in their `types.js` but none declared `connections: [...]`, so the 9 custom request handlers (KnexRawTenant, AuditWrite, ParseCsvAndValidate, CommitRosterImport, CreateSoldier, UpdateSoldier, ArchiveSoldier, CreateMembership, InviteLater) are silently dropped at build time. Every Phase-2 mutation page is broken at runtime with `Request type "<X>" can not be found.` from `@lowdefy/api/dist/routes/request/getRequestResolver.js`. The static verifier did not catch this. See `02-UAT-FINDINGS.md` for the full root-cause analysis.

The chosen fix strategy is "merge all into one plugin" (one of three options weighed in UAT-FINDINGS §"Scope of the fix" — aggregator-as-third-plugin vs. dep-inversion vs. merge). Concretely: create `app/plugins/shifty-plugin/` as a new merged package whose `src/types.js` declares both `connections: ['Knex']` AND `requests: [<9 names>]`, whose `src/connections.js` re-exports `Knex` as a NAMED export, and whose `src/connections/Knex/Knex.js` default-exports `{ schema, requests }` where `requests` is the upstream `@lowdefy/connection-knex` request map spread with the 9 Shifty handlers. All auth callbacks, hooks, middleware, helpers, dispatch modules, and request handler source files move into the merged package as verbatim files; only their `shifty-auth/*` / `shifty-roster/*` / `shifty-audit-writer/*` cross-package imports are rewritten to relative paths. After the move and a successful local sanity build, the three old plugin directories are deleted; `app/lowdefy.yaml` and `app/package.json` are updated to reference the single merged plugin.
