<objective>
Build `tools/snapshot-budibase.ps1`, a PowerShell wrapper around `budi backups --export` that runs from a contributor's local Windows workstation (the same machine that runs the rest of GSD tooling). The script:
1. Accepts a feature-slug CLI argument (mandatory; the human-readable suffix in the tarball filename).
2. SSHes to hpg5 via the canonical plink invocation from CLAUDE.md.
3. Executes `budi backups --export -o /tmp/snapshot.tar.gz` against the running `shifty-budibase-app` container (likely via `docker compose exec -T budibase-app budi backups --export ...`).
4. Copies the tarball back via pscp.
5. Atomically places it at `budibase-exports/YYYY-MM-DD-<feature>.tar.gz` (temp-file + move so an interrupted run never leaves a half-written file in git's working tree).
6. Prints a copy-paste commit message in the form `chore(budibase): snapshot YYYY-MM-DD-<feature>` (does NOT auto-commit — per safety, the user reviews and stages).
7. Optionally outputs a brief checksum + size for the SUMMARY.

Purpose: Resolves BUDIBASE-CONVENTIONS.md §10 open item #4. Per D-04, snapshots are PR-time-only against the live Builder UI on hpg5. Without this wrapper, every PR that touches Builder UI artifacts requires the contributor to remember the exact plink+pscp incantation. The wrapper makes the workflow one-line for contributors and uniform across PRs.

Output:
1. `tools/snapshot-budibase.ps1` (≥60 lines including param block, plink invocation, pscp invocation, atomic file move, commit-message print).
2. `.gitignore` updated to exclude tempfiles in `budibase-exports/` (e.g., `*.tmp`, `*.partial`) but track the committed `.tar.gz`.
3. BUDIBASE-CONVENTIONS.md §10 item #4 marked RESOLVED.
4. SUMMARY documenting the empirical PsExec gating decision + first successful end-to-end run.

Sequencing rationale (per D-06):
- Depends on W0-02 because the first snapshot to validate this wrapper is the post-W0-02 state (the snapshot W0-02 captured inline becomes a regression target — running this wrapper should produce a similar tarball; if drastically different, something's wrong with the wrapper).
- Depends on W0-04 because the snapshot workflow's review story is "the CI gate validated the queries before snapshot; the snapshot is the record". Without W0-04, snapshots would be reviewed in isolation, which is the noisy-CouchDB-diff problem the snapshot is supposed to avoid.

Discretion (per D-01/D-04): tarball naming convention.
- CONTEXT.md "Specifics" line 102: `chore(budibase): snapshot YYYY-MM-DD-<feature>` so reviewers can spot snapshot commits in git log.
- Discretion line 37: whether to include git SHA in filename.
- DECISION (recorded here): NO git SHA in filename. The filename stays `YYYY-MM-DD-<feature>.tar.gz`. Rationale: the git commit that introduces the file is the implicit SHA; the human-readable filename stays scannable in `ls budibase-exports/`. The W0-02 plan made the same call.
- Multiple snapshots same-day-same-feature: rare. If it happens, overwrite is acceptable (per "idempotent" must-have above). A future v1.1 could add a `-<HHmm>` suffix; not for W0-05.
</objective>

<background>
**Canonical plink invocation from CLAUDE.md:**
```
plink -ssh -l claude -pw "Onclaude2103" -batch -hostkey "SHA256:tPg5mYQbJO/9ccGmNGeyJeQQSPXq+C6SL3EHJcbRZMQ" hpg5 "<command>"
```

**Canonical pscp invocation from CLAUDE.md:**
Same auth/hostkey shape, syntax `pscp -pw "<pw>" -hostkey "<hostkey>" <src> <dst>`.

**Container access:**
Per CLAUDE.md "Budibase Deployment on hpg5", the Budibase main app server is `shifty-budibase-app` (image `budibase/apps:3.38.4`). Compose project root is `C:\shifts-manager\`. Compose stack name defaults to `shifty-manager` or `shifty` (verify in compose file or via `docker compose ps`).

**PsExec gating (the critical empirical question for this plan):**
Per CLAUDE.md "Why PsExec for SSH-side docker commands":
- Operations that pull from a registry need PsExec (credential helper requires interactive session).
- Operations on already-cached images do NOT need PsExec.

`budi backups --export` runs INSIDE an already-running container (no pull). On the surface this should NOT need PsExec. But: `budi` is a CLI inside the container that may write to a path mounted from the host; if any of its internal steps invokes Docker Desktop's credential helper (unlikely but possible), PsExec wrapping becomes mandatory.

DECISION TREE for the executor:
1. **First attempt: no PsExec.** Use a plain plink invocation: `plink ... hpg5 "powershell -c \"docker compose -f C:\shifts-manager\docker-compose.yml exec -T budibase-app budi backups --export -o /tmp/snapshot.tar.gz\""`.
2. If that fails with "A specified logon session does not exist" or similar credential-helper error → fall back to PsExec wrap.
3. The script's final shape is whichever worked in step 1 or 2. Document the empirical result in the script header.

**Output path inside the container vs. on the host:**
The container's `/tmp/snapshot.tar.gz` is INSIDE the container's filesystem. To copy it OUT, two options:
- A) `docker compose cp shifty-budibase-app:/tmp/snapshot.tar.gz C:\path-on-host\snapshot.tar.gz` — cleanest. Cp works without registry pulls.
- B) Volume-mount a host directory into /backup at compose-up time, write the tarball there. Requires editing docker-compose.yml. NOT the W0-05 path; defer.

USE option (A). The script chain becomes:
1. SSH to hpg5: run `docker compose exec` to invoke `budi backups --export -o /tmp/snapshot.tar.gz`.
2. SSH to hpg5: run `docker compose cp` to copy `/tmp/snapshot.tar.gz` to `C:\shifts-manager\.snapshot-stage\snapshot.tar.gz` (a temp staging path on hpg5).
3. pscp from `C:\shifts-manager\.snapshot-stage\snapshot.tar.gz` on hpg5 → local `budibase-exports/.YYYY-MM-DD-<feature>.tar.gz.tmp`.
4. Local atomic move: `Move-Item .tmp → .tar.gz`.
5. SSH to hpg5: delete the staging file.

The atomic move (step 4) is the load-bearing safety — it ensures git's working tree never sees a half-copied file.

**Why a script and not just docs:**
The plink+pscp chain is ~8 commands across two hosts. Documenting it as a runbook is the wrong abstraction — every contributor would copy-paste-edit, and slug typos would scatter wrong filenames into `budibase-exports/`. A script with one mandatory arg (`-FeatureSlug`) eliminates the typo class and standardizes the workflow.
</background>

  <files>tools/snapshot-budibase.ps1</files>
  <action>
    Create `tools/snapshot-budibase.ps1`. Structure:

    ```powershell
    <#
    .SYNOPSIS
      PR-time snapshot wrapper around `budi backups --export` against hpg5's shifty-budibase-app container.
    .DESCRIPTION
      Resolves BUDIBASE-CONVENTIONS.md §10 open item #4. Produces budibase-exports/YYYY-MM-DD-<feature>.tar.gz.
      PsExec gating (empirically resolved during W0-05 Task 1, YYYY-MM-DD): <YES PsExec required | NO PsExec required>.
    .PARAMETER FeatureSlug
      Human-readable feature name (lowercase kebab-case). Required. Used as the tarball filename suffix.
    .PARAMETER Date
      Date prefix for the tarball filename. Defaults to today (YYYY-MM-DD).
    .PARAMETER HpgUser
      SSH username for hpg5. Default: claude.
    .PARAMETER HpgPassword
      SSH password for hpg5. Default: pulled from $env:HPG_SSH_PASSWORD if set, else hardcoded fallback (CLAUDE.md canonical).
    .EXAMPLE
      .\tools\snapshot-budibase.ps1 -FeatureSlug "availability-ui"
    #>
    [CmdletBinding()]
    param(
      [Parameter(Mandatory=$true)]
      [ValidatePattern('^[a-z][a-z0-9-]*$')]
      [string]$FeatureSlug,

      [string]$Date = (Get-Date -Format 'yyyy-MM-dd'),

      [string]$HpgUser = 'claude',
      [string]$HpgPassword = $(if ($env:HPG_SSH_PASSWORD) { $env:HPG_SSH_PASSWORD } else { 'Onclaude2103' }),
      [string]$HpgHostKey = 'SHA256:tPg5mYQbJO/9ccGmNGeyJeQQSPXq+C6SL3EHJcbRZMQ',
      [string]$HpgHost = 'hpg5',
      [string]$ContainerName = 'shifty-budibase-app',
      [string]$ComposeFile = 'C:\shifts-manager\docker-compose.yml',
      [string]$BudibaseService = 'budibase-app'
    )

    $ErrorActionPreference = 'Stop'

    # 1. Derive paths
    $TarballName = "$Date-$FeatureSlug.tar.gz"
    $ExportsDir  = Join-Path $PSScriptRoot '..\budibase-exports'
    if (-not (Test-Path $ExportsDir)) { New-Item -ItemType Directory -Path $ExportsDir | Out-Null }
    $LocalTmpPath = Join-Path $ExportsDir "$TarballName.tmp"
    $LocalFinalPath = Join-Path $ExportsDir $TarballName

    # 2. Build canonical plink prefix
    $PlinkPrefix = @("-ssh", "-l", $HpgUser, "-pw", $HpgPassword, "-batch", "-hostkey", $HpgHostKey, $HpgHost)

    # 3. Run `budi backups --export` inside the container
    #    (PsExec wrap: <ENABLE if Task 1 required it, otherwise plain plink>)
    $ContainerExport = "/tmp/snapshot-$Date-$FeatureSlug.tar.gz"
    Write-Host "[1/5] Running budi backups --export inside $ContainerName..."
    # Plain plink path (no PsExec):
    plink @PlinkPrefix "powershell -c `"docker compose -f $ComposeFile exec -T $BudibaseService budi backups --export -o $ContainerExport`""
    # If PsExec was required, swap above for:
    # plink @PlinkPrefix "powershell -c `"`$env:PATH = [Environment]::GetEnvironmentVariable('PATH','Machine') + ';' + [Environment]::GetEnvironmentVariable('PATH','User'); psexec -accepteula -nobanner -i 1 -u $HpgUser -p $HpgPassword cmd /c 'docker compose -f $ComposeFile exec -T $BudibaseService budi backups --export -o $ContainerExport > C:\shifts-manager\snapshot-out.txt 2>&1'`""

    if ($LASTEXITCODE -ne 0) { throw "budi backups --export failed (exit $LASTEXITCODE)" }

    # 4. Stage the tarball on the hpg5 host filesystem
    $HpgStagePath = "C:\shifts-manager\.snapshot-stage\$TarballName"
    Write-Host "[2/5] Copying tarball out of container -> hpg5 host staging..."
    plink @PlinkPrefix "powershell -c `"New-Item -ItemType Directory -Path 'C:\shifts-manager\.snapshot-stage' -Force | Out-Null; docker compose -f $ComposeFile cp ${ContainerName}:$ContainerExport $HpgStagePath`""
    if ($LASTEXITCODE -ne 0) { throw "docker compose cp failed (exit $LASTEXITCODE)" }

    # 5. pscp the staged file back to the local workstation (.tmp)
    Write-Host "[3/5] Copying staged tarball back via pscp -> $LocalTmpPath..."
    pscp -pw $HpgPassword -hostkey $HpgHostKey "${HpgUser}@${HpgHost}:$HpgStagePath" $LocalTmpPath
    if ($LASTEXITCODE -ne 0) { throw "pscp failed (exit $LASTEXITCODE)" }

    # 6. Verify size + atomic move into place
    $size = (Get-Item $LocalTmpPath).Length
    if ($size -lt 1024) { throw "Tarball suspiciously small ($size bytes) — aborting before move" }
    Write-Host "[4/5] Tarball size: $([math]::Round($size/1KB, 1)) KB. Verifying contents..."
    # Basic sanity: tar lists at least one file
    $contents = & tar -tzf $LocalTmpPath 2>$null | Select-Object -First 5
    if (-not $contents) { throw "Tarball appears empty or unreadable" }
    Move-Item -Force $LocalTmpPath $LocalFinalPath

    # 7. Clean up the hpg5 staging file + container tempfile
    Write-Host "[5/5] Cleaning up remote tempfiles..."
    plink @PlinkPrefix "powershell -c `"Remove-Item -Force '$HpgStagePath'; docker compose -f $ComposeFile exec -T $BudibaseService rm $ContainerExport`"" | Out-Null

    # 8. Compute checksum + emit summary
    $hash = (Get-FileHash $LocalFinalPath -Algorithm SHA256).Hash.Substring(0,16)
    $sizeKB = [math]::Round((Get-Item $LocalFinalPath).Length / 1KB, 1)

    Write-Host ""
    Write-Host "Snapshot saved: $LocalFinalPath ($sizeKB KB, sha256:$hash...)"
    Write-Host ""
    Write-Host "Suggested commit message:"
    Write-Host ""
    Write-Host "    chore(budibase): snapshot $Date-$FeatureSlug"
    Write-Host ""
    Write-Host "Stage with:"
    Write-Host "    git add `"$LocalFinalPath`""
    Write-Host "    git commit -m `"chore(budibase): snapshot $Date-$FeatureSlug`""
    ```

    Replace the two `<...>` placeholders in the header + the plink command (PsExec swap) using the empirical result from Task 1.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local workstation → hpg5 SSH | Plink credentials pass over Tailscale; hostkey pinned |
| hpg5 host → shifty-budibase-app container | docker compose exec inside hpg5's interactive session |
| Tarball file → git repo | Snapshot committed; potential for accidentally committing secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03W0-05-01 | Spoofing | hpg5 hostkey verification | mitigate | Hostkey pinned in script param; rejects MITM |
| T-03W0-05-02 | Tampering | Half-copied tarball in working tree | mitigate | Atomic .tmp → final move; verified with size check before move |
| T-03W0-05-03 | Information Disclosure | Snapshot tarball contains secrets | mitigate | `budi backups` per Budibase docs excludes secrets file by default; document this assumption in SUMMARY; future v1.1 adds a pre-commit content scanner |
| T-03W0-05-04 | Denial of Service | Container stopped during export | accept | Script fails fast; user sees clear error; no partial commits possible |
| T-03W0-05-05 | Repudiation | Snapshot integrity over time | mitigate | SHA256 prefix printed at commit time; git history is the audit trail |
| T-03W0-05-06 | Elevation of Privilege | FeatureSlug arg injection | mitigate | ValidatePattern restricts to lowercase kebab-case; no command interpolation paths from user arg into shell |

</threat_model>
