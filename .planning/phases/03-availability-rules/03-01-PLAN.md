Close the P02-HF-05 deferral surfaced in `.planning/phases/02-org-people/02-11-SUMMARY.md` and `.planning/phases/02-org-people/02-UAT-FINDINGS.md`: rebuild the 21 deferred Phase 02 mutation specs across 5 files as Playwright UI-driven flows, and ship the structural verifier (`tools/check-handler-registration.mjs`) that Phase 02 retrospective recommended.

The P02-HF-05 deferral root cause: the 21 specs POSTed directly to `/api/request/<page>/<request>` with `{ payload: { ... } }`. The page YAML's `payload:` block binds every field via `_state:` operators. Direct API callers don't have UI state → every field resolves to `undefined` → schema validation rejects with `ConfigError: Request "X" required property "Y" is missing`. This is structurally incompatible with the Lowdefy `_state:` payload pattern. The Phase 02 closeout (option 1) accepted the deferred gap and tagged v0.2.0-phase2 anyway, with the rebuild explicitly handed off to Phase 03 plan 1 as load-bearing prerequisite for Phase 03's own mutation flows.

This plan is sequenced FIRST in Phase 03 because every subsequent Phase 03 plan adds new mutation handlers + new pages and needs a working UI-flow spec template to copy from. Without 03-01's helper file + rebuilt specs, Phase 03 plans 03-03 through 03-07 would each invent their own locator strategy from scratch (the Phase 02 mistake replayed).

The structural verifier is the second deliverable. RESEARCH Pitfall 1 + Risk R-03-1 both demand it: Phase 03 adds 11 new request handlers to shifty-plugin; each one must (a) be imported into Knex.js, (b) be named in types.js, (c) set `.meta = { checkRead, checkWrite }`, (d) set `.connectionType = 'Knex'`. One forgotten line = silent runtime failure. The 02-11 retrospective explicitly recommended this gate ("Add tools/check-plugin-registration.mjs that statically inspects the BUILD-EMITTED ... after lowdefy build"). 03-01 ships the static-source variant (inspects `connections/Knex/Knex.js` + `types.js` + each handler file); the build-emitted variant is deferred to v1.1 because static analysis catches the same defect class without requiring a running container.
