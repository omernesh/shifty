# Phase 3 — UI Design Contract: Availability & Rules

> Visual and interaction contract for Phase 3 surfaces. The **Phase 02 UI-SPEC is the inherited baseline** — design system (Ant Design 5 + AgGrid 32), spacing scale, typography, color tokens, copywriting conventions, iconography, and a11y rules all carry over verbatim unless explicitly amended in this document.
>
> This document declares **only the new design surfaces Phase 03 introduces**:
> - Shift slots tab inside `team_detail`
> - Template wizard modal (2x12h / 3x8h / Custom)
> - Cross-midnight inline hint on the slot form
> - Planning window open/edit form
> - `shift_instance` date × slot grid (manager preview)
> - `my_availability/{pw_id}` soldier hybrid UI (range blockout + per-slot drill-down, mobile-first RTL)
> - Manager-override entry into `my_availability` from `team_detail`
> - Team Rules tab (8-rule toggle form) + soldier `חוקים אישיים` tab (tightening-only override form)
>

## Interaction Patterns

### Auto-save semantics (Phase 03 specific)

| Surface | Trigger | Confirmation |
|---------|---------|--------------|
| `my_availability` range submit | Click "סמן כלא זמין בטווח" | Message: "סומנו {N} משמרות כלא-זמין" |
| `my_availability` per-slot Switch toggle | Switch onChange | Message: "נשמר" (2s, subtle) — optimistic UI, revert on server error |
| Manager-override write | Switch toggle or range submit | Notification: "הצהרה עבור {name} נשמרה. רשומת ביקורת נכתבה." |
| Rules tab save | Click "שמור חוקים" (explicit) | Message: "חוקי הצוות נשמרו" |
| `חוקים אישיים` save | Click "שמור הידוק" (explicit) | Message: "ההידוק האישי נשמר" |
| Shift slot CRUD | Click "שמור משמרת" / "+ הוסף משמרת" (explicit) | Message: "המשמרת \"{name}\" נוצרה" |
| Planning window open | Click "פתח חלון" (explicit) | Notification: "חלון התכנון נפתח — {N} משמרות נוצרו אוטומטית" |

**Rationale for asymmetric auto-save:** the per-slot availability Switch is the *only* auto-saving control because it's mobile-first and a confirm-button pattern would add taps that bust the <30s SLO. Every other Phase 03 control is desktop-targeted and uses explicit submit.

### Keyboard navigation contract (extends P02 §Accessibility)

- **Tab strip navigation:** arrow-Left/arrow-Right move between tabs (Ant native).
- **Template wizard cards:** Tab into the row → arrow-Left/Right move between cards → Space/Enter selects.
- **TimePicker:** native Ant behavior — type HHmm to set, Tab moves between hours/minutes.
- **`my_availability` per-date list:** Tab into the list → arrow-Down/Up move between rows → Space/Enter expands the focused row → Tab into expanded slot Switches → Space toggles.
- **Rules tab:** Tab walks: Switch → NumberInput → next rule's Switch → ... → final "שמור חוקים" button.

### Form validation display (Phase 03 additions)

- **Cross-midnight is NOT an error**, it's an info hint. Never flagged red.
- **Window length > 30 days:** field-level error on the end_date input + form-level Alert above the CTA.
- **Loosening attempts on `חוקים אישיים`:** persistent Alert above the offending row, not a toast — soldier may not see toasts on phone if app is in background.

## Open Questions / Items Flagged for Planner

1. **Ant Tabs block exposure inside an existing page:** P02 used full-page Cards not Tabs. Phase 03 needs in-page Tab strips for `team_detail` (4 tabs), `planning_window_detail` (3 tabs), `soldier_detail` (3 tabs). Planner verifies `@lowdefy/blocks-antd@5.3.0` exposes `Tabs` block (per skill `reference/04-blocks-core.md` it likely does; confirm at Plan 02-02 time).
2. **Lowdefy media-query support for mobile breakpoints:** the spec assumes `style: { '@media ... }` works inline. If not, fallback is Ant `Row/Col` with responsive `span` props OR sibling blocks with `visible:` conditions on a `_state.viewport_width` value set by an `onPageLoad` handler reading `window.innerWidth`. Planner verifies at Plan time.
3. **AgGrid master-detail in Lowdefy:** `my_availability` desktop pattern would benefit from AgGrid `masterDetail: true` for the per-date drill-down. If Lowdefy doesn't expose this, fallback is `visible:` toggled inline blocks rendered per date.
4. **TimePicker behavior on mobile RTL:** Ant `TimePicker` on iOS may not honor `dir="rtl"` on the dropdown panel. Phase 03 ships the desktop-first slot form; if mobile slot creation becomes a real use case, revisit at Plan time.
5. **Pivot grid valueGetter performance:** the shift_instance grid pivots a flat list into a date × slot matrix. For 30×4 = 120 instances this is fine; if a future window grows to 60 days × 8 slots = 480 instances, the client-side valueGetter may need to move to server-side preview. Phase 03 accepts the simple approach; Phase 04 may need to revisit.
6. **Sidebar tab strip vs. accordion on mobile:** the `team_detail` 4-tab strip at 375px may compress poorly. Planner verifies Ant Tabs `tabPosition: top` with `more: { trigger: 'hover' }` overflow at narrow viewports; fallback is a Selector-as-tab-picker.
