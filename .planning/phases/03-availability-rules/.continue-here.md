# BLOCKING CONSTRAINTS — Read Before Anything Else

> These were discovered through failure during the 2026-05-18 session. Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Schema-write-accepted ≠ runtime-active.** Budibase's `POST /api/screens` accepts JSON with HTTP 200 and the components appear in the Builder UI tree, but the runtime preview iframe will not activate data providers if the fixture omits fields the Builder UI auto-adds. The fix is structural: derive the missing field(s) from a Builder-UI-composed reference screen via diff, NOT by guessing what's missing or by re-running the same dump-and-stare cycle.
- [ ] CONSTRAINT: **`{{ Current User.* }}` bindings only resolve at published-app browser runtime** (see `tools/budibase-cli/SPIKE-BINDINGS.md`). All API-only verification paths (`/api/queries/<id>`, `/api/v2/queries/<id>`, `/api/queries/preview`, with and without CSRF, with prod app-id post-publish) return null. Headless CI verification of bindings is infeasible. The first working screen in the Builder UI preview iframe IS the verification mechanism.

**Do not proceed until both boxes are checked.**
